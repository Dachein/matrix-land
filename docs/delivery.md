# 0.1.0 交付状态

首次交付：2026-10-30；当前源码本地复核：2026-11-04。此仓库以 **Matrix land** 名义交付，仓库名为 `matrix-land`；内部 Frontier Workspace 包名、CLI 与协议保持兼容。不包含其他企业仓库的历史或生产配置。官网保留独立项目、Git 历史与部署，不纳入本软件仓库。

使用 `npm run release:source` 为当前源码生成 `release/matrix-land-0.1.0-candidate.zip`，同时生成候选版本清单与 SHA-256 校验文件。旧 Frontier Workspace 归档属于历史交付，不代表当前品牌版本。当前真实云端试验与剩余验收项见 [安装试验记录](matrixland-installation-pilot.md)。

## 已实现

- 默认使用普通文字 FW 作为未配置 Logo 时的后备显示，安装页、Portal 登录/品牌位置和默认 favicon 均不使用定制几何图形。修改平台名称不会自动改变 FW；用户可以显式提供自己的 Logo 或品牌简写。8 组配色可选，Portal 后备文字跟随当前配色。邮件为客户端兼容保留文字 FW 后备标记。
- Portal 栏目、公开域名、MCP 配置、SDK 与独立 CLI；凭据与目标实例绑定，禁止跨实例沿用连接凭据。
- 本机 Setup：严格配置校验、计划指纹、审阅与执行、加密凭据库、独占锁、步骤记录、失败恢复、会话和进度刷新恢复。
- Cloudflare D1/R2/Queues 创建、六套空库基线、Workers/Pages 编排、服务绑定、独立域名与健康检查。资源创建丢失响应时进行核对；不接管未记录所有权的同名资源。
- 邮箱白名单与验证码自注册、指定邮箱的一次性所有者认领、所有权保护与移交；可选 Entra 应用接入、创建和真实登录验收。
- LiteLLM 已有服务接入、SSH 固定镜像部署、团队与密钥初始化、PostgreSQL 导出与隔离恢复脚本，以及云端限额模型验证。
- 升级前 D1 导出、向前迁移、资源和密钥保留、按版本记录业务验收。关闭模块不自动删除持久化数据。
- 2026-11-02 清理：应用部署的 Auth/Stream 服务绑定及入站邮件路由使用实例配置；移除这些路径对固定 Worker 名的回退。
- 邮件 SDK 0.1.1 显式要求目标实例地址，平台内置下载包、版本与开发指引同步更新；保留 0.1.0 归档及其下载校验。
- 模型验收与远程音频下载使用 Workers 支持的重定向模式并拒绝转发；补充 workerd 模型调用、凭据回收及重定向拒绝验证。

## 尚须真实环境验收

本轮已部署 Matrix land 试用实例，并验证真实邮件登录、管理员认领、知识上传下载、服务健康检查、一次升级和知识数据库隔离恢复。具体证据与未完成项见 [安装试验记录](matrixland-installation-pilot.md)。未安装 LiteLLM 主机、创建 Microsoft 应用或验证模型调用。编译与模拟结果不替代供应商权限、容量和费用验收。

仍须完成所有启用模块的业务验收和容量检查；Entra 登录、模型调用及未启用模块须在配置后单独验收。数据库恢复结果不代表对象存储和整站灾难恢复已完成。记录结果后再判断生产就绪。

当前边界：同一 Cloudflare DNS Zone；Linux 单机 LiteLLM（一个初始模型）；Entra Client Secret；升级为向前迁移，没有一键降级。入站邮件 DNS/MX、企业小程序 AppID 与发布、供应商产品开通属于企业侧配置。新 CLI/SDK 源码未发布 npm，不应使用假定已经存在的公开包版本。

前端 CSS/i18n 健康报告仍包含存量结构和文案整理建议，构建有编辑器等大资源块的体积提示。当前通过不等于所有页面已经完成同等深度的视觉审查，也不等于完成独立安全审计。

安装步骤、权限、秘密管理和恢复方式见 [installation.md](installation.md)。长期设计规范见[产品蓝图](frontier-workspace-product-blueprint.md)及[集成设计](frontier-workspace-setup-integrations.md)。
