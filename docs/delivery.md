# 0.1.0 交付状态

日期：2026-10-30。此仓库是独立的 Frontier Workspace 源码库，使用新的 Git 历史；不包含其他企业仓库的历史或生产配置。

## 已实现

- 默认 FW 几何图标，统一安装页、Portal 登录/品牌标记和默认 favicon。修改平台名称不会自动改变 FW；用户可以显式提供自己的 Logo 或品牌简写。8 组配色可选，Portal 图标跟随当前配色。邮件为客户端兼容保留文字 FW 后备标记。
- Portal 栏目、公开域名、MCP 配置、SDK 与独立 CLI；凭据与目标实例绑定，禁止跨实例沿用连接凭据。
- 本机 Setup：严格配置校验、计划指纹、审阅与执行、加密凭据库、独占锁、步骤记录、失败恢复、会话和进度刷新恢复。
- Cloudflare D1/R2/Queues 创建、六套空库基线、Workers/Pages 编排、服务绑定、独立域名与健康检查。资源创建丢失响应时进行核对；不接管未记录所有权的同名资源。
- 邮箱白名单与验证码自注册、指定邮箱的一次性所有者认领、所有权保护与移交；可选 Entra 应用接入、创建和真实登录验收。
- LiteLLM 已有服务接入、SSH 固定镜像部署、团队与密钥初始化、PostgreSQL 导出与隔离恢复脚本，以及云端限额模型验证。
- 升级前 D1 导出、向前迁移、资源和密钥保留、按版本记录业务验收。关闭模块不自动删除持久化数据。

## 尚须真实环境验收

本轮没有开通云资源、安装远程主机、签发真实密钥、创建 Microsoft 应用或发送真实验证邮件。上述编译与模拟结果不代表供应商账号权限、网络、证书、邮件送达和真实模型费用已经验收。

首次部署必须完成：邮箱送达与所有者认领、DNS/TLS、已启用模块的真实业务操作、Entra 登录（如启用）、云端模型调用（如启用）及实际备份恢复演练。记录结果后再判断生产就绪。

当前边界：同一 Cloudflare DNS Zone；Linux 单机 LiteLLM（一个初始模型）；Entra Client Secret；升级为向前迁移，没有一键降级。入站邮件 DNS/MX、企业小程序 AppID 与发布、供应商产品开通属于企业侧配置。新 CLI/SDK 源码未发布 npm，不应使用假定已经存在的公开包版本。

前端 CSS/i18n 健康报告仍包含存量结构和文案整理建议，构建有编辑器等大资源块的体积提示。当前通过不等于所有页面已经完成同等深度的视觉审查，也不等于完成独立安全审计。

安装步骤、权限、秘密管理和恢复方式见 [installation.md](installation.md)。长期设计规范见[产品蓝图](frontier-workspace-product-blueprint.md)及[集成设计](frontier-workspace-setup-integrations.md)。
