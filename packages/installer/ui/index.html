企业与外观

Cloudflare

分别在 Cloudflare 创建两个令牌：平台运维令牌用于部署与升级工作区；用户资源执行令牌由后台保管，在校验用户权限后用于应用资源创建和发布。

如何创建？需要哪些权限？

创建步骤

  1. 先填写 Account ID 和 Zone ID，再点击对应的 Generate。
  2. 在 Cloudflare 核对账号、域名及下方权限；Zone Resources 必须选择 Specific zone 和目标域名，不能保留 All zones。若页面没有预填，请选择“创建自定义令牌”。
  3. 点击“继续查看摘要”→“创建令牌”，复制显示的 Token，粘贴回对应输入框。
  4. 分别创建平台运维令牌和用户资源执行令牌，复制到对应输入框；然后生成并审阅安装计划。

第一阶段的权限用途

Cloudflare 权限访问级别解决的问题
Account Settings、ZoneRead核对目标账号及域名归属
Workers Scripts、Cloudflare PagesEdit部署工作区，以及用户创建的应用
Workers Routes、DNSEdit把服务和应用连接到域名
D1、Workers R2 Storage、Workers KV StorageEdit创建和管理数据库、对象存储及 KV 资源
QueuesEdit知识库索引队列；选择知识库时加入平台运维令牌

模板会按所选模块调整权限。请在 Cloudflare 核对资源范围只包含目标账号和域名。这些是账号或 Zone 级权限，资源命名前缀不代表权限隔离。

两个令牌的职责

平台运维令牌（Platform Operations Token）由机构运维人员管理，供安装器部署、初始化及升级平台。它解决“平台如何安装与维护”的问题。

用户资源执行令牌（User Resource Execution Token）由平台后台服务保管，供工作室执行用户已获授权的应用资源创建、部署、发布等操作。它解决“用户操作如何落到云资源上”的问题。

执行令牌不是用户登录凭据，不发给每个用户。权限由平台按用户、任务和资源校验；普通内容操作、已有应用的使用或模型对话，并不因此都需要调用 Cloudflare 管理 API。

本安装流程分别配置两枚 Token，独立更换和撤销。当前两者仍有较多账号级权限重叠，分开配置并不自动形成每用户的 Cloudflare 权限隔离。令牌有效期应覆盖实际需要；不要在依赖它的操作仍需运行时撤销。

Token 不会在应用用户的浏览器中下发；安装后进入加密凭据库，运行所需凭据作为后台服务 Secret 配置。凭据库密码单独保管。
